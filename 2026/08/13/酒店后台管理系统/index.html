酒店后台管理系统

一、为什么选择 Vben Admin ?

在前端项目中，后台管理系统所涉及到的技术栈比较广，也比较贴近现实生活，同时这类项目也比较成熟，做起来不容易翻车。最终选择 GitHub 上的 vue-vben-admin，原因主要有四点：

1.企业级架构:monorepo 组织、多应用支持、完善的权限体系

2.TypeScript 全覆盖:完整的类型提示，对学习 TS 很有帮助

3.丰富的组件封装:表格、表单、搜索都有现成的封装

4.Vite + pnpm:开发体验好

二、项目结构初探

用 pnpm 管理的 monorepo 结构，这是我第一次接触这种组织方式：

在写这个页面的时候遇到了一个小问题：页面间数据不同步

问题描述：

在分类管理里新增了一个分类，回到商品新增页面，下拉选择框里看不到这个新分类。

原因分析：

因为两个页面的数据是独立加载的。商品表单的 loadCategoryOptions() 只在页面挂载时调用一次，而且数据存在组件的局部变量 categoryOptions 里。两个页面之间不共享状态，所以新增分类后，商品页不知道分类数据已经变了。

解决方法：

每次进入商品表单页面时重新加载分类列表：

这样每次进入表单页面都能拿到最新的分类数据。

但让我第一次意识到：在 SPA 中，页面之间不会自动共享数据，需要主动刷新或借助全局状态管理。

四、Mock 数据

开发阶段，所有 API 请求都经过了项目内置的 Mock 服务器。

Vben Admin 的设计是：开发环境下自动启动一个基于 Nitropack 的 Mock 服务器，监听 localhost:5320，提供完整的 RESTful API 响应：

  • 认证接口：登录/登出/刷新 Token

  • 用户接口：用户信息

  • 电商接口：商品/分类/订单 CRUD

  • 系统管理接口：菜单/部门/角色/用户

Mock 数据用 @faker-js/faker 动态生成，每次刷新都不一样。

这样做的优点是：前端开发完全不依赖后端，自己就能独立跑通全流程，实现前后端分离，极大地提高了效率并且符合真实场景。

五、部署上线：Vercel

![alt text](/img/酒店后台管理系统/截屏2026-08-14 14.33.44.png)

部署选择了 Vercel，主要是因为免费，和 GitHub 无缝集成，HTTPS 自动配置。

推送步骤：

1.代码推送到 GitHub

2.在 Vercel 导入仓库

3.Vercel 自动识别为 Vite 项目，构建命令和输出目录自动配好

4.点击 Deploy，几分钟后就上线了

部署上线的时候遇到一个小问题:Vercel 报错说找不到构建输出

报错显示为:No Output Directory named “dist” found after the Build completed.

因为这是 monorepo 项目，框架是 Vite，默认构建输出是 dist，但 monorepo 里 dist 在 apps/web-antd/dist 下面，不在项目根目录。

解决方法:

在 Vercel 项目设置中配三个参数：

Root Directory:apps/web-antd

Build Command:pnpm build

Output Directory:dist

配置好之后 Redeploy 一下就好了，就这个小问题给我报错了七次，花了快半小时才调好。

六、项目总结

技术收获:

1.Vue 3 + TypeScript 实战

这是第一次在完整项目中使用 TypeScript，受益很大：

  • 学会了定义接口类型，比如商品的 ProductItem、ProductListParams，整个数据流都有类型约束

  • 写代码时编辑器自动提示字段名和方法签名，减少了反复翻 API 文档的时间

2.企业级框架的二次开发能力

Vben Admin 不是一个简单的模板，而是一个完整的企业级框架。在这过程中学会了：

  • 理解 monorepo 的组织方式——40+个 workspace 包各自负责什么

  • 在现有框架上做扩展，而不是从零开始写

  • 按框架的约定来添加页面、路由、API，而不是随心所欲地写

3.VxeTable 组件的深度使用

以前写表格要手动管理数据加载、分页、loading 状态、搜索条件联动，代码又长又乱。VxeTable 的代理配置把这些全部自动化了：

  • 声明列配置、搜索表单配置、分页配置
  • 只需要写一个 query 回调函数返回数据
  • 表格自动处理加载动画、分页切换、搜索联动

4.前端工程化

这个项目让我第一次接触了前端工程化的概念。简单说，就是通过工具和规范来保证代码质量和开发效率：

  • pnpm 管理依赖，monorepo 结构让40+个共享包可以统一管理

  • TypeScript 提供了类型约束，写代码时 IDE 就能给出提示，很多 bug 在编译阶段就被发现了

  • 环境变量区分开发和生产，不需要手动改 API 地址

  • Git + Vercel 实现推送即部署，不需要手动上传文件

思维提升：

1.从”写代码”到”做产品”的转变

课堂作业关注的是”能不能跑起来”，而真实项目要考虑的是：

  • 数据完整性：删除分类时检查是否有商品关联，不能直接删

  • 用户体验：表单验证要即时反馈，操作要有确认和提示

  • 边界情况：接口加载失败要有兜底，不能白屏

2.技术选型

新增/编辑商品时，选择了独立路由页面而非弹窗，这是基于用户体验和可维护性的理性决策：

  • URL 可分享、可刷新不丢失状态

  • 后续扩展空间更大

  • 组件职责清晰，不与列表页耦合

3.工程化思维

  • 不要从零造轮子：Vben Admin 提供了完善的基础设施，学会了站在巨人肩膀上做扩展

  • 先上线再迭代：项目不追求一步到位，部署上线后根据反馈可以持续改进，先做出来再完美

最后，其实这个项目还有一个小缺点：我部署在 Cercel 的只是一个纯前端，我后续会补齐它的mock数据
